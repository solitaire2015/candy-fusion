# Candy Fusion 简版 PRD

状态：需求初稿，供设计和开发协作。更新日期：2026-10-27。

## 1. 产品目标

开发一款横屏微信小游戏，让玩家免费体验水果糖果的物理堆积与合成。以简单操作、连续合成的反馈和冲击个人最高分为主要吸引力，最终可在微信小游戏平台公开游玩。

参考 DNF 手游中用户提供的休闲游戏录像。目标是接近其可爱氛围与操作体验，正式美术资产独立制作。平台提审、主体及发布条件在上线准备阶段核实，本文件不代表已经具备发布资格。

## 2. 核心循环

查看待掉落糖果与下一颗预览 → 左右调整落点 → 点击掉落 → 糖果受重力影响碰撞、滚动 → 同级糖果合成并增加分数 → 继续投放 → 堆积满足结束条件 → 查看成绩并再次挑战。

策略来自落点选择、合成顺序、大小糖果的空间安排和连续合成的机会。

## 4. 首版范围建议

### 必须形成的完整闭环

- 一个普通合成模式，一套糖果等级链和一个瓶子场景。
- 待投放糖果、落点指示、左右控制、掉落操作和下一颗预览。
- 稳定的物理碰撞与同级合成，支持连续合成。
- 当前分数、本机最高分、游戏结束结算和再次挑战。
- 基础合成动效及操作反馈，必要的玩法提示。
- 微信开发者工具运行和手机横屏真机验证。

### 后续再评估

炸弹模式、广告、付费、联网排行榜、账号同步、活动任务、皮肤和社交功能。首版不依赖这些功能，也不需要先搭建业务后端。免费目标不随迭代默认改变。

## 5. 页面与交互

**对局页**：左侧放当前分数、最高分和等级链，下方放左右按钮；中央放透明瓶子和落点提示；右侧放下一颗预览及醒目的掉落按钮。保留安全区，避免操作按钮与系统手势冲突。

**结算层**：对局停止投放，显示本局分数、最高分及是否刷新纪录，提供再次挑战和返回入口。重开需要清理上一局物体、计分和待处理的合成事件。

**操作建议**：左右键按住连续移动、松开停止；掉落后用短暂冷却或状态限制避免重复投放。具体移动速度、冷却时长和允许下一次投放的时机由原型确定。

## 7. 首版验收方向

- 在微信开发者工具及选定的手机测试设备上完成一整局：调整落点、投放、合成、结算、重开。
- 同级接触按规则产生一个后继糖果，不重复合成或重复计分；不同等级正常碰撞。
- 多颗糖果同时接触、连续合成及瓶内密集堆积时，不出现持续穿透、异常飞出或卡死。
- 已确定的警戒线与宽限规则可复现地触发结束；结束后不再投放或继续改变最终成绩。
- 本机最高分在重开和重新进入时正确读取；切后台恢复不因时间跳变引起物理异常。
- 横屏不同长宽比下，瓶子和操作按钮完整可见且可点击；具体设备和帧率目标在技术方案中记录。
- 发行包使用原创或获授权资产，不包含参考录像、截图或临时访问链接。

验收项是后续实现目标，当前尚未执行游戏功能测试。

## 8. 首版实现记录（2026-10-27）

技术路线已确定为 TypeScript + Canvas 2D + Matter.js，Node.js 24.22.1。当前已经实现普通模式、11级糖果、计分与本机最高分、合成特效、暂停、判输和重开，浏览器与微信小游戏使用同一套玩法和画面代码。原型参数及运行方式以 [README](../README.md) 和 `src/config.ts` 为准，仍可通过试玩调整。

目前最大等级保留；初始投放前4级，权重40/30/20/10；投放不计分；新投放有1.2秒宽限，糖果顶部持续超出警戒线2秒结束。切后台暂停，返回后主动继续；不保存未结束对局。

已完成自动化规则、密集堆积、平台入口和浏览器操作验证，并在微信开发者工具使用测试号导入显示横屏游戏。第7节中涉及 iPhone / Android 真机、实际帧率与音频的验收项仍待设备验证，不将开发工具或 VM 测试等同于真机验收。


## 9. 试玩反馈调整（2026-10-27）

修复合并移除支撑后上层休眠刚体未被唤醒导致的偶发悬空，合并批次结束后重新唤醒整堆糖果。糖果半径统一乘以1.05以小幅增加空间压力，瓶子尺寸、随机权重、计分与判输规则保持原值，后续以手机试玩继续调节。

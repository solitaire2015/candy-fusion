# 开发与微信预览

本工程采用 TypeScript + Canvas 2D + Matter.js。浏览器和微信小游戏共用玩法及画面代码，通过 `Platform` 接口接入不同的输入、图片、音频、存储和前后台事件。

## 开发环境

- Node.js **24.22.1**，版本记录于 `.nvmrc` / `.node-version`。Node 只用于本机构建，不会打包到手机。
- npm（随 Node 安装）。
- 微信开发者工具；本地先选工具的小游戏测试号，正式发布配置自己的**微信小游戏 AppID**。

使用 nvm 的环境可执行：

```sh
nvm install
nvm use
npm install
npm run dev
```

如果不使用 nvm，可通过现有版本管理器选择 24.22.1；不要为本项目改动其他工程的全局配置。浏览器预览地址以 Vite 输出为准，默认是 `http://127.0.0.1:5173`。

## 常用命令

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

- `dev`：浏览器开发与热更新。
- `typecheck`：TypeScript 静态检查。
- `test`：物理和玩法规则自动化测试。
- `build`：类型检查、浏览器构建、微信小游戏构建。
- `build:web`：只构建浏览器版本至 `dist/web`。
- `build:wechat`：只构建小游戏至 `dist/wechat`。
- `preview`：预览已经构建的浏览器版本。

浏览器用左右方向键调整落点，空格掉落，也可使用画面上的触摸按钮。具体规则和当前验证结果见项目 README。

## AppID 与微信开发者工具

AppID 是小游戏在微信平台的身份，不需要在编写玩法代码之前取得。浏览器开发和构建可立即进行。本机工具的小游戏测试号已通过开发测试和手机预览打包，可直接用手机微信扫描工具生成的二维码。正式体验版、上传发布应配置自己的小游戏 AppID，普通小程序的 AppID 不应假定可以直接用于小游戏。

构建模板默认填写 `testappid`，仅是占位，本机导入时实际出现过“不合法”提示。点击导入界面的“测试号”后，工具分配了有效的测试 AppID，并成功导入显示横屏画面、生成手机预览二维码。该 ID 已存入 Git 忽略的 `wechat/project.local.config.json`，当前机器重新构建会保留；其他开发者需要自己选择测试号或配置正式 ID。测试号不等于正式发布身份。

配置方法一：在命令行构建时指定（仅作用于本次命令）：

```sh
WECHAT_APP_ID=wx0123456789abcdef npm run build:wechat
```

这里的示例 ID 必须替换为微信后台提供的真实 ID。

配置方法二：创建本地文件 `wechat/project.local.config.json`：

```json
{
  "appid": "wx0123456789abcdef"
}
```

该本地文件已被 Git 忽略。优先级为环境变量、local 文件、模板默认值。修改 AppID 后需重新构建。

在微信开发者工具中导入 **`dist/wechat`** 文件夹，项目类型选择小游戏。不要导入仓库根目录或 `dist/web`。配置文件和 `game.js` 已由构建脚本生成。开启浏览器开发服务并不能代替小游戏构建；修改代码后重新运行 `npm run build:wechat`，再在工具中编译。

小游戏通过 `game.json` 设置横屏。最高分写入本机存储，无需服务器。前后台切换通过平台适配层通知对局；恢复时的交互由游戏层管理。

## 文件布局

```text
src/
  app.ts           共用 Canvas 画面和输入控制
  config.ts        等级链与玩法参数
  game.ts          Matter.js 物理与对局规则
  platform.ts      平台接口与浏览器适配
  main.ts          浏览器入口
  wechat.ts        微信小游戏入口与微信适配
public/assets/     正式运行素材
scripts/
  build-wechat.mjs  微信打包、配置与本地音频校验
wechat/            小游戏配置模板
```

微信构建仅复制 `public/assets` 中允许的图片、音频与 JSON 文件。正式音效与背景音乐为预先生成的本地 MP3，构建会检查四个必需文件存在且非空。`docs/references` 中的原游戏视频和截图不会进入发行目录。更换正式美术时应维持碰撞边界与可见糖果尺寸的一致性。

## 验证边界

自动化测试通过只能证明对应规则检查通过，浏览器试玩也不能代替微信真机测试。交付前仍需在 iPhone 和 Android 中检查横屏安全区、多点触控、音效、切后台恢复、密集堆积性能及一整局结束重开。公开发布的主体、类目与提审要求应以实际微信后台为准。

## 微信预览兼容性与重建

手机预览打包比模拟器运行更严格。实际首次预览暴露出 `onBest?.(...)` 的可选链导致 `Unexpected token .`，现已将微信输出目标降为 **ES2017**；TypeScript 源码仍可使用现代语法，由 esbuild 转换。构建与微信冒烟检查会确认输出无可选链和空值合并运算符，避免同类回归。

构建先在导入目录外暂存文件，再原子替换，最后发布入口。不变文件不改 mtime，工具的私有配置保留；这能减少工具监听到不完整文件而误触发编译的情况。浏览器发行目标独立设置。

## 合并支撑与休眠回归（2026-10-27）

用户反馈：下方合并后，上层偶发悬空，受到另一颗糖果撞击才继续掉落。本地在自然静置8秒后的堆叠中稳定复现：上层进入isSleeping，支撑合并后连续模拟3秒，旧代码上层y坐标仍为432.3961；手动唤醒后可滚落瓶底。

原因来自当前Matter.js0.20.0的休眠机制：重力积分跳过休眠物体，Composite.remove不唤醒依赖该支撑的其它物体，而碰撞运动达到阈值时又会唤醒它们。合并处理现于同一物理步的所有合并结束后，对剩余糖果统一Sleeping.set(false)，涵盖间接受支撑的上层并重置临近休眠计数，不改变重力或人为添加推力。

两个新增回归测试使用真实自然休眠与自动碰撞合并，不通过强制休眠伪造前置状态。浏览器复放同一场景也验证上层自然落下。17项测试、类型检查、浏览器与微信构建通过。

同时按用户要求，将半径集中乘以1.05，面积增加约10.25%，其余难度参数不变。参数位于src/config.ts。正确唤醒使堆积更充分，因此密集场景测试将最多投放数由240延至320，仍要求完整触发判输、保持边界并冻结结果。
